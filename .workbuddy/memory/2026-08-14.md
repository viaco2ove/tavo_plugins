## 读 MCP Server.md 后修正认知（重要）
- 源：`md/tavo_help/plugin_help/MCP Server.md`（docs.tavoai.dev/cn/guides/mcp-server/）。
- **MCP Server 默认关闭** → 彻底解释了连接超时/断开：tavo 桌面端 MCP Server 需手动开启（设置→MCP Server→选访问范围→启用）。**重新启用时 URL/IP 可能变**（DHCP），故每次联网前必须重读 `.env` 的 `tavo_mcp_url`，不要缓存旧 IP。
- **角色写入工具支持 裸 CC 兼容 data / 完整 CCv2/CCv3 wrapper / SillyTavern 角色 wrapper**（line 21）。即 `avatar` 是头像一等字段，路径就是 CCv3 的 `data.avatar`（data URI）。**这反驳了"update 不支持头像"的猜想**——之前失败更可能是：①传了完整 `data` 对象带计算字段导致 update 忽略 avatar；②1.1MB 超限被静默丢弃（1×1 测试那次 MCP 是否真连上存疑）。
- 文件工具（tavo_file_save 等）**必须传 chatId，即使 scope=global**（之前我传 chatId=6 正确）。
- 导入冲突默认报错，可 `conflict:"overwrite"`/`"saveAs"` 重试。
- **修正后的头像方案**：联网后用 `upload_avatars.py` —— 先把 >300KB 压缩到 ~280KB，再拉 `tavo://schemas/character` 确认真实字段；优先 `tavo_character_update` 写 `data.avatar`，验证仍空则回退 `tavo_character_import`（CCv3 wrapper + conflict:overwrite）。

## 头像上传成功（18:2x，已完成）
- **关键机制（实测，重��复用）**：
  - `tavo_character_update` 任何形式（裸 data / 完整 CCv3 wrapper）都**不持久化 `avatar`**（只同步文本字段）。
  - `tavo_character_import_card` 是唯一能存头像的路径，且为**整卡替换**：须传「完整 `data` 对象 + avatar」，只传 `{name,avatar}` 会丢性格/对白。
  - 它按 name **新建而非覆盖** → 产生重复卡。故流程 = 导入新卡 → `tavo_chat_update(id, chat:{characterIds:[新ids]})` 重绑 → `tavo_character_delete` 删旧卡。
  - import 工具真名是 `tavo_character_import_card`（非 `tavo_character_import`）；其入参无 `conflict` 字段（conflict 仅 theme）。
  - 头像 data URI：原图 1.1MB 太大，压到 87–201KB（PNG 无损优化不够则转 JPEG q≈80–88）。
