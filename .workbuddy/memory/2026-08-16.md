## AVD offline 故障排查与恢复（00:00）
- 用户报 `adb devices` 显示 `emulator-5554 offline`
- **根因1**：模拟器进入"半死"状态——QEMU 进程还在（pid 27168），但 5554/5555 端口已不监听，adbd 挂了，握手失败
- **根因2**：第一次冷启动 `-no-snapshot-load` 时 `netsimd`（网络模拟守护）反复崩溃循环（每 3-13 秒重启一次），卡住 QEMU 初始化；日志暴露诱因：系统设了 HTTP 代理 `http://127.0.0.1:7890/`（Clash/V2Ray）干扰 netsim 的 host DNS
- `-no-proxy` 不是 emulator 有效选项（会直接退出）
- **修复**：`taskkill /F /IM emulator.exe /IM qemu-system-x86_64.exe` 清进程 → 正常启动 `emulator -avd Pixel_8_Pro -netdelay none -netspeed full -no-boot-anim`（用快照恢复，不带 `-no-snapshot-load`，不 unset 代理环境变量但也不传无效选项）→ 75 秒 boot 完成

## 气泡插件优化：逐条改属性 → 纯 CSS 控制（00:05）
- **触发**：用户要求"改为控制 css 而不是逐条改属性"
- **旧方案问题**（`plugins/toonflow_story_style/ui/story_style_panel.html` 的 `<script>`）：
  - `tagBubbles()` 遍历 `[class*=message]`/`[class*=bubble]` 元素，每个 `getComputedStyle` 读背景色，跟缓存的主题色做容差比对，相等的打 `data-tf-bubble` 标记
  - 每次新消息 `message:changed` → 清空所有标记 → 全 DOM 重扫 → 重新比对 → 重新标记 → 重新注入 CSS
  - 脆弱（主题色 AA 通道/HSL 变化就失效）、慢（每元素强制 layout）、新气泡要重扫、flat 风格未处理（bug）
- **反编译确认真实 DOM**：`script/debug/tavo_app_webview/app_apk_reverse/extracted/.../dist/css/bundle.min.css` 里有语义化 class：
  - `.tav-bubble`（基础，`background:#fff`）
  - `.tav-user-bubble`（用户气泡，默认 `#c3f2fd` 浅蓝）
  - `.tav-character-bubble`（角色气泡，默认 `#f5f5f5` 浅灰）

- **新方案**（v1.2.0）：

  3. 拖滑块只 `documentElement.style.setProperty('--tf-bubble-alpha', alpha)` 一个变量，零 DOM 扫描、零 API
  4. 新气泡自动命中（选择器永久生效），不再需要 `message:changed` 重扫
  5. 主题色变化：监听 `chat:opened` → `loadThemeColors()` 重读一次写 RGB 变量（不重注入 CSS）
  6. 默认色 fallback 取自 bundle.min.css（user [195,242,253] / character [245,245,245]），读主题失败也能工作
- **保留**：单条/多条逻辑（hideHistory/showAll 走 message.hidden API，是数据层不是样式层）
- **删除**：`tagBubbles` / `colorEq` / `_bubbleRGBs` / `_tagged` / `data-tf-bubble` 标记机制 / `injectBubbleCSS`+`removeBubbleCSS` 的重注入逻辑 / `message:changed` 事件订阅

## 气泡插件再优化：消除切换模式弹框（v1.2.0 → v1.3.0，00:11 用户报）
- **症状**：用户截图显示切换「单条/多条」时弹"是否允许修改聊天消息？"确认框，不丝滑
- **根因**：v1.2.0 单条模式实现是 `tavo.message.update(m)` 设置 `m.hidden = true`，每条消息一次 API 调用都会触发 Tavo 的权限确认（即使一次确认后批量通过，也仍打扰；N 条就 N 次或至少 1 次）
- **正确思路**（用户要求"控制 css 而不是逐条改属性"的延伸）：
  - 气泡是 CSS 控制的（`.tav-user-bubble`/`.tav-character-bubble`/`.tav-bubble-style-flat`），可见性也应用 CSS 控制，跟透明度同思路
  - 不调任何 message API → 0 弹框
- **新方案**：
  - 注入永久 CSS：`body.tf-style-single .tav-item-message:not([data-tf-last]) .tav-bubble { display:none!important }`（同时隐藏 wrapper 避免布局塌陷）
  - JS 只做：① 切换模式时 `document.body.classList.toggle('tf-style-single')`；② 给最后一条消息项打 `data-tf-last` 标记（CSS 选择器排除它）
  - 新消息到达：只重打最后一条标记（O(1)），零 API
  - 监听：`message:added`（ui fragment）+ `chat:opened`（entry.js，都监听保险）
- **迁移**：v1.2.0 及之前残留的 hidden=true 消息必须清掉（否则切回多条模式也会被错误隐藏）
  - `entry.js` 加 `migrateClearHidden()`：检查 `tavo.get('tf_style.migrated_v130') === '1'`（global scope 一次），否则遍历所有消息把 hidden 改回 false（一次性接受弹框）
- **改动文件**：
  - `manifest.json` version 1.2.0 → 1.3.0
  - `entry.js` 重写：删 applySingle/applyMulti；加 migrateClearHidden + markLastBubble
  - `ui/story_style_panel.html`：CSS 注入块加 single 模式规则；删 hideHistory/showAll；applyMode 改 body class toggle；初始化切 body class + 调 markLastBubble；监听 message:added 重打标；hint 文案更新
  - `locales/zh-CN.json` + `en.json` 文案改写（新机制说明）

## 修复单条模式显示第一条而非最新消息（v1.3.0 → v1.3.1，00:56）
- **症状**：单条模式（仅最新台词）不显示最新，只显示第一条消息。
- **根因**：Tavo 消息列表是「最新在顶部」布局（反编译 bundle.min.js 确认 `scrollToCurrentBottom` => `listElement.scrollTo({top:0})`，即最新内容在 scrollTop=0 处；列表为虚拟窗口渲染 `start/end/total/loadFn`）。`markLastBubble()` 却用 `items[items.length-1]`（最后一个 DOM 子节点）= 最旧可见消息 = 第一条，于是单条模式把第一条留下、隐藏其余。
- **修复**：`markLastBubble()` 改为标记纵轴最靠上（getBoundingClientRect().top 最小）的 `.tav-item-message`，即最新一条。UI fragment 与 entry.js 两处同步修改；顺带更新注释与 hint 文案（"仅显示最新一条"）。
- **版本**：manifest 1.3.0 → 1.3.1；`plugin_install.py` 重装到 AVD，verify enabled=True。
- **验证**：AVD 进群聊，切「单条」应显示最新台词；发新消息后自动更新为最新（message:added 重打标）。

## 单条模式改为纯 CSS 控制 .kuibao-list-item（v1.3.2 → v1.3.3，01:50）
- **背景**：v1.3.1/1.3.2 用 JS 给最新 `.tav-item-message` 打 `data-tf-last` 标记，方向判断反复出错（用户实测单条模式显示"倒数第2"而非最新），坐标法 / 从最后一个 .kuibao-list-item 往前找两种启发式都不稳。
- **用户决策**："直接用 css 控制吧"，给方案：
  ```css
  .kuibao-list-item { display: none; }
  .kuibao-list-item:first-child { display: block; }
  ```
  即最新一条 = 列表第一条（:first-child），由 CSS 直接选，彻底不要 JS 标记。
- **改动**（plugins/toonflow_story_style）：
  - `ui/story_style_panel.html` 注入 CSS 改为 `body.tf-style-single .kuibao-list-item{display:none!important}` + `body.tf-style-single .kuibao-list-item:first-child{display:block!important}`（限定单条模式作用域 + !important 覆盖 Tavo 自身样式）。
  - 删除 `markLastBubble()` 函数及所有调用（applyMode / chat:opened 初始化 / message:added 监听），单条可见性纯靠 CSS。
  - `entry.js` 同步删除 markLastBubble 与 message:added 监听，仅保留 migrateClearHidden。
  - manifest 1.3.2 → 1.3.3。
- **安装**：`plugin_install.py` 装到 AVD，verify v1.3.3 enabled=True。
- **风险**：依赖用户"第一条=最新"的截图观察。若 Tavo 列表实为 column-reverse（DOM first-child 在视觉底部=最旧），则 :first-child 会显示最旧；届时一行改成 `:last-child` 即可。用户重进聊天验证。
