# 整合版流程（编排插件为中心枢纽）
## 核心设计
编排插件（multi_character_stage）作为整个流程的**中心枢纽**：
- 意图识别、章节判定、事件进度、记忆状态全部收敛到编排插件
- 通过 window API 与各插件通信（事件管理器、记忆管理器）
- 发言插件已整合进编排插件（阶段二发言 Agent）

## 流程一：用户发送后
```
用户发言
  ↓ input:beforeSend（编排插件接管）
  ↓ ① 意图识别（keyword/LLM）
     ├─ @记忆管理 → 交给 memory_manager 处理，自己让出
     ├─ @事件进度检测 → 交给 event_manager 处理，自己让出
     └─ 普通对话 → 进入编排流程
  ↓ ② 编排前状态获取（并行）
     ├─ window.tfStoryJudge.checkAndAdvance() → 章节+事件状态
     ├─ buildMemoryContext() → 角色参数卡（HP/等级/当前行为）
     └─ tmmIntent.refresh() → 异步触发记忆刷新
  ↓ ③ 编排 Agent（阶段一）→ 输出 JSON
     ├─ speaker / role_type / motive
     ├─ await_user / trigger_memory_agent
     └─ 注入记忆 cast、章节状态、意图提示
  ↓ ④ 发言 Agent（阶段二）→ 输出台词
  ↓ ⑤ tavo.message.append → 角色消息落地
  ↓ ⑥ 章节状态同步 → window.tfStoryJudge.checkAndAdvance() 更新进度
  ↓ 语音合成（voice 插件监听 message:added）
  ↓ 播放完毕 → 循环
```

## 流程二：开场白后
```
开场白播放（event_manager bootSequence）
  → 编配插件自动编排
  → 发言 Agent → 台词
  → voice 插件播放
  → 循环编排
```

## 整合后的编排插件职责
- **意图识别**：keyword 快路径 + LLM 细分类（6 种意图）
- **章节判定**：window.tfStoryJudge.checkAndAdvance()
- **事件进度**：同 window.tfStoryJudge（内部调用 evaluateEventProgressByAi）
- **记忆状态**：buildMemoryContext() + tmmIntent.refresh()
- **编排决策**：阶段一 Agent，注入 memory.cast + 章节状态
- **发言生成**：阶段二 Agent（已整合发言插件逻辑）

## 插件优化
### 把章节判定 和事件进度 做到 编排插件
方案	做法	优点	缺点
A. 移到编排插件内	把 evaluateEventProgressByAi + evaluateChapterOutcomeByAi 复制/引用到 multi_character_stage，在编排前先判定章节 + 推进事件	所有编排逻辑集中一个插件	跟 event_manager 重复/冲突
B. 通过事件通信	编排前发一个 tf_story:check_chapter 事件，event_manager 监听并返回判定结果	解耦，不重复代码	需要改造 event_manager 支持回调

如果这样的话，意图识别和记忆管理也是编排的一部分了
