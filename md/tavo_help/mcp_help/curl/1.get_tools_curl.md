可以，完全可以通过 curl 来测试。MCP 协议底层就是 JSON-RPC 2.0 + HTTP，curl 完全能胜任。

根据你提供的地址 http://127.0.0.1:7347/mcp，需要按以下步骤操作：

第一步：初始化（获取 Session ID）-》无状态模式 不需要

curl -s -i -X POST http://127.0.0.1:7347/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer 28pd43" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2025-03-26",
      "capabilities": {},
      "clientInfo": {"name": "curl-test", "version": "1.0"}
    }
  }'

注意响应头中的 Mcp-Session-Id 字段，记下来，后续请求需要带上它？
这个 MCP 服务器没有返回 Mcp-Session-Id。这说明它使用的是无状态模式（每个请求独立认证，靠 Bearer Token 鉴权），不需要 session。
这其实是好事——后续请求更简单，不用管 session ID 了。

第二步：发送初始化完成通知 -》无状态模式 不需要

curl -s -X POST http://127.0.0.1:7347/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer 28pd43" \
  -d '{
    "jsonrpc": "2.0",
    "method": "notifications/initialized"
  }'

这一步通常返回 202 No Content 或 204，表示初始化完成。

第三步：获取工具列表（核心）


curl -s -X POST http://127.0.0.1:7347/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer 28pd43" \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/list"
  }'

返回结果中会包含所有可用函数，每个函数包含：
name — 函数名
description — 功能描述
inputSchema — 参数定义（JSON Schema 格式）
无需 ：-H "Mcp-Session-Id: <session-id>" \

第四步（可选）：调用某个工具

curl -s -X POST http://127.0.0.1:7347/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer 28pd43" \
  -d '{
    "jsonrpc": "2.0",
    "id": 3,
    "method": "tools/call",
    "params": {
      "name": "工具名",
      "arguments": {"参数名": "参数值"}
    }
  }'

💡 小贴士

如果服务器是无状态模式（stateless），可能不需要 Mcp-Session-Id，可以跳过前两步直接发 tools/list 试试
如果 token 不是 Bearer 方式，也可以试试改成 ?token=28pd43 作为查询参数
如果返回 SSE 流式响应（text/event-stream），结果会以 event: message + data: {...} 的格式返回，取 data: 后面的 JSON 即可
