## 用户发言后的完整响应链路

```
用户输入 → input:beforeSend → 消息落历史 → message:added → generation:prepare → LLM生成 → message:added(NPC发言)
```

### 第一层：`input:beforeSend`（发送前拦截）

**记忆管理器插件** 先拦截：

```
用户发送 "@记忆管理 xxx"
    ↓
tmm 的 input:beforeSend 匹配前缀
    ↓
cancel() 阻止 tavo 原生流程
    ↓
append 用户消息（hidden=false，正常显示）
    ↓
走 intentMode 分支：
  - keyword 模式：确定性规则直接更新参数卡
  - model_api 模式：调 runMemoryAgent() → LLM → 更新记忆
  - auto 模式：先 keyword，识别不出 → fallback LLM
```

**事件管理器插件** 的 `input:beforeSend` 只管 `@事件进度检测` 指令，不拦截普通对话。

---

### 第二层：`message:added`（消息落地后）

两个插件同时监听此事件：

```
┌─────────────────────────────────────────────────────────────┐
│                    message:added 触发                        │
└──────────────────┬──────────────────────────────────────────┘
                   │
         ┌─────────┴──────────┐
         ▼                   ▼
  ┌──────────────┐    ┌─────────────────┐
  │  记忆管理器插件  │    │   事件管理器插件   │
  │  (tmm)        │    │  (tf_story)      │
  └───────┬───────┘    └────────┬─────────┘
          │                     │
          ▼                     ▼
  turnsSinceRefresh++    judgeAndAdvance()
  ┌────────────┐        ┌─────────────────────────┐
  │ 触发条件:   │        │ ① 章节结局判定 LLM        │
  │ - 关键词   │        │   evaluateChapterOutcomeByAi()
  │ - 轮数达标 │        │   (chapter_judge agent)  │
  └─────┬──────┘        ├─────────────────────────┤
        │               │ ② 事件进度检测 LLM        │
        ▼               │   evaluateEventProgressByAi()
  runMemoryAgent()       │   (event_progress agent)  │
  → LLM 调用            ├─────────────────────────┤
  → 更新 summary/       │ ③ 事件状态机推进          │

                        └────────┬────────────────┘
                                 │
                          结果写入 tf_progress
                          （currentPhase / currentEvent）
```

### 第三层：`generation:prepare`（LLM 生成前）

**编排插件**（mcs）在这里完全接管：

```
tavo 原生 generation:prepare 触发
    ↓
event_manager 的 generation:prepare（boot 未 ready 时拦截）
    ↓
mcs 的 generation:prepare（监听）
    ↓
ORCH_FLAG = true（防止并发）
    ↓
检查编排模式 tf_story.edit.orchestration
    ↓
'plugin' 模式 → mcs 完全接管
    ↓
两阶段编排：
  ┌─────────────────────────────────────────┐
  │ 阶段一：编排 LLM（speaker prompt）        │
  │ 调用 window.tf_llm.callDirect()          │
  │ → 返回 JSON: {speaker, motive,           │
  │   event_summary, await_user,            │
  │   trigger_memory_agent, ...}            │
  │                                         │
  │ ★ 这里才是"谁说话、为什么说话"的决策点      │
  └──────────────────┬──────────────────────┘
                     │
                     ▼
  ┌─────────────────────────────────────────┐
  │ 阶段二：台词 LLM（speaker prompt）        │
  │ 调用 window.tf_llm.callDirect()          │
  │ → 返回该角色的台词正文                    │
  └──────────────────┬──────────────────────┘
                     │
                     ▼
  append 角色消息（tavo.message.append）
    ↓
trigger_memory_agent=true 时：
  → 调用 window.tmmIntent.refresh()
  → 触发记忆管理器后台刷新
    ↓
ORCH_FLAG = false
    ↓
generation:success
```

## 直接回答你的问题

> 谁去消费 sendmsg？

**不是单一消费者，而是多个钩子按顺序串联：**

| 阶段 | 钩子 | 插件 | 职责 |
|------|------|------|------|
| 发送前 | `input:beforeSend` | 记忆管理器 | 拦截 `@记忆管理` 指令，直接处理 |
| 发送前 | `input:beforeSend` | 事件管理器 | 拦截 `@事件进度检测` 指令 |
| 消息落地 | `message:added` | 记忆管理器 | 后台刷新记忆 |
| 消息落地 | `message:added` | 事件管理器 | 章节判定 + 事件进度追踪 |
| 生成前 | `generation:prepare` | 事件管理器 | boot 状态门控 |
| **生成前** | **`generation:prepare`** | **编排插件** | **接管 LLM，两阶段生成角色发言** |

> 记忆管理插件内部有意图识别 agent 和记忆管理 agent？

**有，但分层：**

- **意图识别**（`window.tmmIntent.classifyLLM`）：内置一个独立的 LLM prompt，专门识别 6 种意图（create_task / exit_task / query_progress / game_action / normal_dialog / memory_update），用极小参数（temperature=0, maxTokens=100）独立调用。**但普通对话不走这个**，只在 `input:beforeSend` 拦截 `@记忆管理` 指令时触发。

- **记忆管理 agent**（`runMemoryAgent`）：内置完整 `MEMORY_RULES` prompt，调 `window.tf_llm.callDirect()` 生成 `{summary, facts, tags, player_card_patch, npc_card_patches}`。**触发条件是轮数/关键词**，不是意图识别结果。

> 编排插件内部调用事件 agent / 章节 agent / 记忆管理 agent？

**编排插件不直接调用这些 agent。** 它只负责"角色说话"这件事：

- **章节 agent**（`evaluateChapterOutcomeByAi`）：在 `message:added` 里由事件管理器调用，不在编排链路里
- **事件 agent**（`evaluateEventProgressByAi`）：同样在事件管理器的 `judgeAndAdvance` 里
- **记忆管理 agent**：编排插件只在 `trigger_memory_agent=true` 时才调用 `window.tmmIntent.refresh()`，是**异步后台触发**，不等结果

**编排插件和事件/记忆管理器是平行关系，不是嵌套调用。** 编排插件依赖事件管理器的状态（tf_progress 的 phase/event），但不直接调用它的 LLM。
