## issue 诚实回答

---

### 1. 能否局域网 API 让 Workbddy 等工具直接为安卓手机的 tavo 创建故事和角色甚至是章节和世界书、备份数据等
[❌]不考虑走官方的mcp ，由插件自己实现可否

- [✅] **插件是否可以通过 HTTP 请求实现局域网 API 客户端**
  - ✅ **可以**。插件声明 `permissions: ["network"]` 后，可以通过 `fetch()` 发起 HTTP 请求
  - 可以主动上传数据到服务器，也可以从服务器拉取数据
  - **但**：插件只能是客户端，不能作为服务端暴露端口让 Workbddy 调用

- [❌] **插件是否可以作为服务端被 Workbddy 调用**
  - ❌ **不行**。tavo 插件运行在 WebView 里，无法监听端口暴露 API
  - 手机必须作为服务端的话，这条路走不通

- [❌] **结论**
  - 单向可行：插件主动把数据 POST 到你的服务器（✅）
  - Workbddy → tavo 方向不可行，除非你在手机上跑一个独立的服务端 App（❌）

---

### 2. 是否完全抛弃 tavo 自带的"群聊"，用插件自己实现"多人角色故事"的能力
以下内容均非直接在官方的"群聊"功能里实现

- [❌] **插件是否可以在单个聊天框里气泡显示角色的头像、台词列表显示多个角色的台词**
  - ❌ **不行**。tavo 消息气泡的渲染完全由 tavo 控制，插件的 `htmlFragments` 只能**追加新 UI**，不能覆盖或修改已有消息的显示方式
  - 插件无法控制消息气泡的样式、头像、角色名等渲染细节

- [❌] **插件是否可以像"Toonflow-game"一样切换多条台词和单条台词的显示模式**
  - ❌ **不行**。同上，插件改不了消息渲染

- [✅❌] **插件是否可以提供创建故事的能力和创建角色的能力。还是故事章节等。为故事添加世界书等**

  - [✅] **创建角色** - ✅ **可以**。`tavo.character.create()` 可以创建角色
  - [✅] **创建世界书** - ✅ **可以**。`tavo.lorebook.create()` 可以创建世界书
  - [ ❌] **创建"故事"** - ❌ **不行**。tavo 数据模型里根本没有"故事"这个实体，插件调用官方 API 创建不了不存在的东西
  - [❌ ] **创建"章节"** - ❌ **不行**。tavo 没有章节概念
  - [ ❌] **故事-章节-角色-世界书的层级关系** - ❌ **不行**。tavo 没有这套结构，插件最多在变量里自己维护一套逻辑，但 tavo 界面层面不认

**结论**：插件能做到的只有"创建角色"和"创建世界书"，但这两者之间以及它们与"故事"之间没有层级关系。

### 3. 一键上传或自动同步数据备份
[✅] 插件是否可以获取备份数据，调用自定义接口上传数据。

- [✅] **插件是否可以获取备份数据**
  - ✅ **可以**。`tavo.character.export()`、`tavo.lorebook.export()`、`tavo.file.export()` 等可以导出数据

- [✅] **插件是否可以调用自定义接口上传数据**
  - ✅ **可以**。声明 `permissions: ["network"]` 后用 `fetch()` POST 到你的服务器

- [✅] **结论**
  - 导出 + 上传这条路 ✅走得通
  - 但"自动同步"需要服务器端配合，你自己开发服务端存数据和版本管理

### 4. tavo MCP 有啥用的
[❌] 插件是否可以自定义 mcp 函数 
[❌] 插件的业务是否可以被tavo MCP函数调用

- [❌ ] **插件是否可以自定义 MCP 函数**
  - ❌ **不行**。MCP 函数是 tavo 官方提供的，插件无法扩展 MCP

- [❌ ] **插件的业务是否可以被 tavo MCP 函数调用**
  - ❌ **不行**。插件运行在 WebView 里，无法被 MCP 调用
  - MCP 是外部客户端调用 tavo，不是 tavo 调用插件

**结论**：插件和 MCP 是两个独立的东西，互不相通。

---

### 5. tavo 插件有哪几种服务形式，可不可以自定义各种 UI 和业务

**插件可以完全自定义 UI 和业务逻辑**。

插件能提供的功能：

| 类型 | manifest 配置 | 说明 |
|------|---------------|------|
| 设置页 | `contributes.settings` | switch、slider、select、textarea 等 |
| 侧边栏动作 | `contributes.sidebar` | 点击执行操作 |
| 输入框动作 | `contributes.inputActions` | 输入框 + 菜单 |
| 聊天 UI 片段 | `contributes.htmlFragments` | 悬浮面板、状态栏等 |
| 插件主入口 | `entry.js` | 所有业务逻辑 |

**支持的 Hooks**：

| Hook | 触发时机 |
|------|----------|
| `chat:opened/closed/updated` | 聊天生命周期 |
| `message:added/updated/deleted` | 消息变化 |
| `generation:prepare/success/error/cancelled` | 生成生命周期 |
| `input:beforeSend/afterSend` | 输入发送前后 |

**自定义 UI**：完全支持
- 可以写任意 HTML/CSS/JavaScript
- 可以访问 `tavo.*` 所有 API
- 支持悬浮面板（必须可拖动）、按钮、表单等
- 需要开启「高级渲染」

**关键限制**：
- ❌ 插件不能修改 tavo 原生消息气泡的渲染（头像、样式、位置等）
- ❌ 插件不能隐藏或覆盖已有消息
- ✅ 插件只能追加新 UI 元素，或通过 `tavo.message.append()` 追加新消息

|------|------|
| 1. 插件自己实现局域网 API | ✅ 插件可以作为 HTTP 客户端主动上传/拉取数据；❌ 不能作为服务端被 Workbddy 调用 |
| 2. 抛弃群聊自己实现 | ❌ 插件改不了消息渲染；✅ 只能创建角色和世界书（没有故事/章节概念） |
| 3. 数据备份上传 | ✅ 导出 + fetch POST 可以做到，需要自己开发服务端 |
| 4. 插件自定义 MCP | ❌ MCP 是官方固定的，插件无法扩展，插件也不能被 MCP 调用 |
| 5. 插件自定义 UI | ✅ 可以自定义悬浮面板、按钮、表单等；❌ 不能修改原生消息气泡渲染 |
