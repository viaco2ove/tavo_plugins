# toonflow_story_multi-character_Stage 设计文档

> 为 tavo 打造的多人角色故事台插件，移植并简化 Toonflow-game 的多 Agent 叙事引擎。

## 1. 定位与目标

**一句话定位**：让 tavo 的群聊从「多个角色各说各话」变成「有编排的群戏」。

**核心问题**：
- tavo 现有群聊模式：用户同时 @ 多个角色，各角色独立回复，缺少叙事编排
- 目标效果：角色之间能自然互动、推进剧情、有主次之分

**设计原则**：
1. **插件化**：不依赖服务端，用 tavo 现有 API 实现
2. **轻量化**：优先规则路由，AI 仅在必要时调用
3. **可插拔**：与现有 `toonflow_story_memory_manager` 插件协同

## 3. 核心模块

### 3.1 发言路由引擎 (SpeakerRouteEngine)

**职责**：决定「谁来说下一句话」

**路由规则**（按优先级）：

| 优先级 | 条件 | 模式 | 说明 |
|--------|------|------|------|
| 1 | 用户直接 @ 指定角色 | direct | 用户明确指定 |
| 2 | 上一轮有角色未回应 | sequential | 承接上一轮 |
| 3 | 重要角色 + 高风险动机 | premium | 告白/冲突/关键节点 |
| 4 | 旁白/万能角色 + 短动机 | fast | 过场/环境补句 |
| 5 | 普通 NPC | normal | 常规回复 |
| 6 | 无人发言超过 N 轮 | npc_auto | NPC 自主行为 |

**数据结构**：

```typescript
interface SpeakerDecision {
  role: string;           // 角色名
  roleId: string;         // 角色 ID
  roleType: 'npc' | 'narrator' | 'wildcard' | 'player';
  motive: string;         // 发言动机
  mode: 'direct' | 'sequential' | 'premium' | 'fast' | 'normal' | 'auto';
  nextRoleHint?: string;  // 下一个发言者提示
  confidence: number;     // 置信度
}
```

### 3.2 台词生成器 (SpeakerAgent)

**职责**：根据 speaker 决策生成具体台词

**三档生成模式**：

| 档位 | 适用 | 模型 | 延迟目标 |
|------|------|------|----------|
| T0 模板 | 旁白/万能角色 | 无 AI | <200ms |
| T1 轻量 | 普通 NPC | 本地模型 | 1-3s |
| T2 高质量 | 关键角色/关键节点 | 云端模型 | 3-8s |

**输入结构**：

```typescript
interface SpeakerInput {
  role: string;                    // 当前说话人
  roleType: string;                // 角色类型
  motive: string;                  // 发言动机（来自编排）
  currentStage: string;            // 当前阶段
  recentDialogue: DialogueItem[];  // 最近 3 条对话
  userMessage?: string;            // 用户最新输入
  areaContext: AreaContext;        // 区域上下文
  memorySummary?: string;          // 记忆摘要
}
```

### 3.3 区域/发言聚焦系统 (AreaFocusSystem)

**职责**：控制「谁可以发言」，不是地图系统

**状态模型**：

```typescript
interface AreaContext {
  mainArea: string;           // 当前主区域 "阴间-奈何桥"
  activeRoles: string[];      // 可参与发言的角色
  remoteRoles: string[];      // 远程可发言角色（如电话里的人）
  exceptionRoles: string[];   // 本次例外角色
}
```

**维护规则**：
- 用户移动时更新主区域 + 激活角色列表
- 章节切换时重置激活角色
- 异常角色单次生效后清除

### 3.4 记忆协同 (MemoryIntegration)

与 `toonflow_story_memory_manager` 协同：

```typescript
// 从记忆插件读取
const memory = tavo.get('tmm') || {};

// 写入侧：触发记忆刷新
// 读取侧：注入到编排上下文
```

**注入格式**：

```
【记忆上下文】
故事摘要：{summary}
最近事实：{facts.join('；')}
关键标签：{tags.join('、')}
动态背景：{dynamicBg}
```

## 4. 数据模型

### 4.1 插件状态 (mcs.*)

```typescript
interface MultiCharacterStageState {
  version: 1;
  config: {
    enabled: boolean;
    npcAutoTurn: boolean;      // NPC 自主发言
    npcAutoInterval: number;   // 无用户发言 N 轮后触发
    speakerMode: 'auto' | 'manual';
    memoryIntegration: boolean;
  };
  context: {
    currentSpeaker: string | null;
    areaContext: AreaContext;
    dialogueHistory: DialogueItem[];  // 最近 N 条
    turnsSinceUserInput: number;
    pendingSpeakers: string[];        // 待发言队列
  };
  characters: {
    [roleId: string]: {
      name: string;
      type: 'npc' | 'narrator' | 'wildcard';
      isKey: boolean;              // 是否关键角色
      lastSpokeAt: number;         // 上次发言时间戳
      speakingCount: number;       // 当前事件发言次数
    }
  };
}
```

### 4.2 对话项

```typescript
interface DialogueItem {
  id: string;
  role: string;
  roleType: string;
  content: string;
  timestamp: number;
  speakerMode: string;        // T0/T1/T2
  isUserMessage: boolean;
  areaAtTime: string;         // 发言时的区域
}
```

## 5. 核心流程

### 5.1 用户消息流程

```
用户发送消息
    ↓
input:beforeSend → 解析 @角色/指令
    ↓
message:added → 记录对话历史
    ↓
speakerRouteEngine.decide() → 确定下一 speaker
    ↓
speakerAgent.generate() → 生成台词
    ↓
生成结果写入聊天（隐藏消息或模拟角色发言）
    ↓
generation:complete → 检查是否需要继续 NPC 发言
    ↓
（需要）→ 循环 speakerRouteEngine + speakerAgent
（不需要）→ 等待用户下一轮
```

### 5.2 NPC 自主发言流程

```
context.turnsSinceUserInput >= npcAutoInterval
    ↓
speakerRouteEngine.decide({ mode: 'auto' })
    ↓
speakerAgent.generate({ mode: 'fast' | 'normal' })
    ↓
写入对话（标记为 NPC 自主发言）
    ↓
更新 turnsSinceUserInput
```

### 5.3 场景切换流程

```
用户输入包含移动意图（"去XX"/"来到YY"）
    ↓
意图识别 → 更新 areaContext.mainArea
    ↓
根据新区域配置更新 activeRoles
    ↓
注入区域切换旁白（如需要）
```

## 6. tavo API 映射

| Toonflow 概念 | tavo API | 说明 |
|--------------|----------|------|
| 多角色对话 | `tavo.chat` + `tavo.message` | 读取/写入消息 |
| 角色信息 | `tavo.character.find/get` | 获取角色设定 |
| 编排上下文 | `generation:prepare` 注入 | 修改生成 prompt |
| 记忆状态 | `tavo.get('tmm')` | 读取记忆插件数据 |
| 异步执行 | fire-and-forget | 不阻塞主流程 |
| 隐藏消息 | `tavo.message.append({ hidden: true })` | 存储中间状态 |

## 7. 与记忆插件的协同

### 7.1 数据流

```
toonflow_story_memory_manager
    ↓ 读取
mcs (编排上下文)
    ↓ 写入
tavo.generate() → 台词生成
    ↓
toonflow_story_memory_manager
    ↓ 触发刷新（message:added）
记忆更新
```

### 7.2 注入协调

- 记忆插件的 `generation:prepare` 先执行
- 本插件的 `generation:prepare` 后执行
- 两者都向 `event.text` 追加内容，顺序无关

## 8. 简化决策（v1 范围）

| 不做 | 原因 |
|------|------|
| 完整任务系统 | 太复杂，v1 只做基础叙事编排 |
| 章节/阶段管理 | tavo 没有章节概念，用区域代替 |
| 语音生成 | 依赖外部服务，v1 不做 |
| 服务端同步 | 用 tavo 现有 chat/message API 足够 |
| 向量检索 | 用记忆插件的简单记忆足够 |
