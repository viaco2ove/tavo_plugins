# 设计文档：toonflow_story_memory_manager

## 1. 源 agent 分析（Toonflow-game `story_memory_manager`）

### 1.1 职责

记忆管理器是 Toonflow-game 记忆系统的**写入侧**，由 `runStoryMemoryManager()` / `refreshStoryMemoryBestEffort()` 驱动（`NarrativeOrchestrator.ts:5097`），编排完成后**后台异步**执行，不阻塞台词返回。职责：

1. 提炼最近对话与事件增量中的新事实、标签、摘要；
2. 维护「动态全局背景」（故事世界观的当前演变状态）；
3. 识别用户/NPC 的长期状态变化，输出角色参数卡 patch（等级、经验、hp/mp、物品、技能、`role_key_information` 等）；
4. 结果写回会话 state（`memorySummary` / `memoryFacts` / `memoryTags` / `dynamicWorldGlobalBackground`），供编排师、角色发言器等下游 agent 消费。

### 1.2 输入

| 输入 | 源 |
|------|----|
| system prompt | 数据库 `story-memory` 提示词，缺省回退代码内保底版 |
| worldName / worldGlobalBackground | world 表 |
| dynamicWorldGlobalBackground | state（上一轮记忆管理器输出，缺省回退 memorySummary） |
| chapterTitle | chapter 表 |
| 当前事件（index/kind/summary/facts/memory_summary/memory_facts） | 事件运行时上下文 |
| eventDeltaText | 本轮事件增量消息 |
| recentDialogue | 最近对话（compact: 4 条×420 字；full: 10 条×1600 字） |
| currentMemory / currentFacts / currentTags | state 上一轮记忆 |
| playerCard / narratorCard / npcCards | 角色动态参数卡快照 |
| worldClock | 仅自由模式（tick/时段/天气） |
| worldKnowledge | 世界书匹配条目（仅参考，不照抄进 summary/facts） |

### 1.3 输出（JSON）

```json
{
  "summary": "新的故事摘要",
  "facts": ["新事实1"],
  "tags": ["标签1"],
  "player_card_patch": { "level": 2, "exp": 40, "items": [], "other": [] },
  "npc_card_patches": [
    { "role_id": "npc_xxx", "role_name": "某角色", "patch": { "items": [], "role_key_information": "身份备注\n【当前行为】..." } }
  ],
  "dynamic_world_global_background": "新的动态全局背景"
}
```

patch 字段白名单：`raw_setting, personality, appearance, voice, skills, items, equipment, other, gender, age, level, level_desc, exp, next_level_exp, hp, mp, money, role_key_information`。数值规则：`age/level/exp/next_level_exp/hp/mp/money` 必须是数字；默认 `next_level_exp = level * 100`；升级时 `level+1`、扣旧阈值、hp/mp 按 `100 + level*10` 回满；模糊成长只写 `other`。

### 1.4 关键机制

- **compact/full 双模式**：`shouldUseCompactMemoryPayload()` 按厂商/模型判断（lmstudio、autodl、lite/mini/flash 系列走 compact），压缩上下文体积。
- **异步原则**：发言成功 → 先提交消息 → 后台排队记忆更新 → 静默更新 memorySummary。
- **`@记忆管理` 直接指令**：用户输入以 `@记忆管理` 开头时视为对长期记忆和参数卡的直接管理指令，必须直接更新 summary/facts/tags 和对应 patch。
- **健壮解析**：模型输出可能带代码块/多余文本，经 `unwrapModelText` + JSON 安全解析 + 字段映射表双路径提取，patch 经 sanitize 过滤非法字段。

## 2. 到 tavo 的能力映射

| Toonflow 概念 | tavo 对应 | 说明 |
|--------------|----------|------|
| 会话 state（memorySummary/Facts/Tags/dynamicBg） | `tavo.set/get/update('tmm.*', value, 'chat')` | chat 作用域变量，随聊天导出/克隆 |
| world/chapter 元信息 | `tavo.chat.current()` + 角色 description | 聊天名当世界名；无章节概念，用变量 `tmm.world` 承载自定义世界观 |
| recentMessages / recentDialogue | `tavo.message.find([-N, -1])` | 取最近 N 条消息 |
| 事件增量 eventDeltaText | 自上次刷新以来的消息（按 `tmm.meta.lastIndex` 截取） | 无事件系统，以消息楼层增量替代 |
| 角色参数卡 | 变量 `tmm.cards`（内存态参数卡） | **默认不写回** `tavo.character.update`（弹确认框）；可选手动写回 |
| worldClock（自由模式） | 变量 `tmm.worldClock` | v2 |
| 世界书注入 | 宿主原生世界书 + 变量 `tmm.worldKnowledge` 补充 | 插件不重复实现世界书匹配 |
| 编排后后台刷新 | `message:added` Hook + fire-and-forget | 新消息落库后异步刷新 |
| 编排师/发言器注入记忆摘要 | `generation:prepare` 改写 `event.text` | model-only 注入，不改已保存消息 |
| 台词快照 | 隐藏消息快照（可选） | 见 5.4 |
| `@记忆管理` 直接指令 | `input:beforeSend` 拦截 + `tavo.generate` | 命中后 `event.cancel()` |
| 记忆管理器模型 | `tavo.generate(prompt, { context: false })` | 用当前聊天绑定的模型 API |
| `tavo.memory`（宿主长记忆） | 可选同步 | 关键记忆可镜像到宿主长记忆，默认关 |

## 4. 核心流程

### 4.1 异步记忆刷新（写入侧）

```
角色消息保存（message:added）
    ↓
节流检查：距离上次刷新 ≥ interval 轮 且 当前无刷新在途
    ↓ 满足
采集输入：
  - chat = await tavo.chat.current()
  - msgs = await tavo.message.find([lastIndex, -1])   // 事件增量
  - recent = 最近 dialogueWindow 条消息               // 最近对话
  - cards  = tavo.get('tmm.cards')                    // 当前参数卡
  - meta   = tavo.get('tmm.meta')                     // 上轮 summary/facts/tags/dynamicBg
    ↓
buildMemoryUserPrompt(payload, compactMode)
    ↓
tavo.generate(userPrompt, { context: false, settings: { temperature: 0.3 } })
（system 规则以"指令前缀"方式并入 prompt 头部，因 tavo.generate 无独立 system 参数）
    ↓
parseMemoryResult(rawText)：unwrap → JSON 安全解析 → sanitize patch
    ↓
tavo.update('tmm', { meta: {...}, cards: mergeCards(cards, patches) })
    ↓
（可选）tavo.memory.append(criticalFlags) 镜像到宿主长记忆
```

失败处理：`tavo.generate` 异常仅 `console.warn`，保留旧记忆，不弹错、不重试（与源系统 best-effort 一致）。

### 4.2 记忆注入（读取侧）

`generation:prepare` 中构造注入块（对应源系统编排师 prompt 的「当前记忆摘要」）：

```
[记忆上下文（模型参考，不要在正文中提及本段）]
故事摘要: {summary}
最近事实: {facts，分号连接}
关键标签: {tags}
动态全局背景: {dynamicWorldGlobalBackground}
用户当前状态卡: {level/hp/mp/money/items 精简行}
```

约束：
- 注入总预算：compact ≤ 400 字、full ≤ 900 字，超长按优先级截断（summary > 状态卡 > facts > tags > dynamicBg）；
- 记忆为空时不注入，避免污染请求；
- handler 5 秒上限内只读变量 + 字符串拼接，不调用 `tavo.generate`，确保不超时。

### 4.3 `@记忆管理` 直接指令

```
input:beforeSend → event.text 以 "@记忆管理" 开头？
    ↓ 是
event.cancel('正在执行记忆管理指令')
    ↓
构造指令型 user prompt（沿用 system 规则 + 指令原文 + 当前记忆 + 参数卡）
    ↓
tavo.generate → parseMemoryResult → 写回 tmm
    ↓
toast 提示结果摘要（更新了几条事实/几个 patch）
```

### 4.4 台词快照（轻量替代）

源系统把记忆快照写进每条台词。tavo 侧改为：每次刷新成功后，以**隐藏消息**追加一条 `[记忆快照] {...}`（可配置关闭），用于回溯与调试；删楼即随消息作用域消失。默认关闭以节省存储。

## 5. 数据模型（chat 作用域变量 `tmm`）

```js
tavo.set('tmm', {
  version: 1,
  meta: {
    summary: '',              // 故事摘要
    facts: [],                // 事实（上限 factCap，FIFO）
    tags: [],                 // 标签（上限 tagCap）
    dynamicBg: '',            // 动态全局背景
    lastIndex: 0,             // 上次刷新处理到的消息楼层
    updatedAt: 0,             // 上次刷新时间戳
    turnsSinceRefresh: 0,     // 节流计数
  },
  cards: {
    player: { level: 1, exp: 0, next_level_exp: 100, hp: 100, mp: 100, money: 0, items: [], skills: [], other: [], role_key_information: '' },
    npcs: {}                  // key = 角色名或 id
  },
  world: '',                  // 用户自定义世界观/世界背景（可空）
  worldClock: null,           // v2
}, 'chat')
```

- 角色识别：`message.characterId` → `tavo.character.get(id).name` 作为 `cards.npcs` 的 key；无法识别的 assistant 消息归入 narrator。
- patch 合并规则：数组字段（items/skills/other）按「新增追加、明确失去移除（patch 中以 `-` 前缀表示）」合并；数值字段直接覆盖；`role_key_information` 保留原身份备注 + 追加/替换 `【当前行为】` 段。

## 6. 触发与节流

| 项 | 默认 | 说明 |
|----|------|------|
| 刷新间隔 | 每 3 轮消息 | 源系统按事件触发；tavo 无事件系统，用轮次近似 |
| 关键词强触发 | 关系/背叛/获得/失去/任务/真相 等可配置 | 增量消息命中关键词立即刷新，近似源系统 8 类触发条件 |
| 并发防护 | `refreshing` 内存标志 | 在途时跳过，防止连发消息触发多次 |
| 注入开关 | 开 | 关则只做记录不注入 |
| 冷却 | 无 | 强触发后重置节流计数 |

## 7. 设置项（settings.schema）

| key | 类型 | 默认 | 说明 |
|-----|------|------|------|
| `enabled` | switch | true | 总开关 |
| `payloadMode` | select | compact | compact / full，对应源系统双模式 |
| `refreshInterval` | slider | 3 | 每 N 轮刷新（1–10） |
| `dialogueWindow` | slider | 6 | 最近对话窗口条数（2–20） |
| `factCap` / `tagCap` | slider | 12 / 8 | facts/tags 上限 |
| `injectEnabled` | switch | true | 是否 generation:prepare 注入 |
| `injectBudget` | slider | 400 | 注入字符预算（100–1500） |
| `syncHostMemory` | switch | false | 是否把关键记忆镜像到宿主 `tavo.memory` |
| `snapshotEnabled` | switch | false | 隐藏消息快照 |
| `triggerKeywords` | textarea | （默认词表） | 强触发关键词，分号分隔 |
| `worldSetting` | textarea | 空 | 世界背景（注入到 prompt 的 [世界] 区块） |
| `systemPromptOverride` | textarea | 空 | 覆盖内置 system 规则（高级） |

## 8. 权限与 Hooks 清单

```json
"permissions": ["input", "message", "generate", "variable", "file"]
```

Hooks：`input:beforeSend`、`message:added`、`generation:prepare`、`chat:opened`。
入口：`sidebar`（手动刷新 / 查看记忆 / 导出快照 / 写回角色卡）+ `htmlFragments`（状态面板，可拖动悬浮）。

## 9. 风险与边界

1. **`tavo.generate` 在 generation 期间被调用的嵌套风险**：刷新任务由 `message:added` 触发，此时本轮生成已结束，安全；但 handler 内不等待生成结果（fire-and-forget），避免占用 Hook 等待配额。
2. **5 秒 handler 上限**：`generation:prepare` 只做同步读变量 + 拼接；`input:beforeSend` 命中 `@记忆管理` 时先 `event.cancel()` 再异步执行，不受 5 秒限制约束。
3. **模型输出不稳定**：沿用源系统的 unwrap + 安全解析 + sanitize 三道防线；解析失败保留旧记忆。
4. **参数卡写回弹窗**：默认关闭自动写回；手动写回动作逐角色执行，用户可随时取消。
5. **多插件冲突**：注入块使用明确标记 `[记忆上下文...]`，不与其他插件注入混淆；变量全部在 `tmm` 命名空间下。
6. **聊天克隆/导入**：chat 作用域变量随聊天迁移，无需重写；`chat:opened` 做 version 迁移检查。

## 10. 版本计划

- **v1.0**：本文档范围（写入/注入/直接指令/面板/导出）。
- **v1.1**：快照回溯 UI；facts 去重优化；按角色过滤注入。
- **v2.0**：世界时钟 + NPC 当前行为（自由模式移植）；深度记忆检索器（检索+凝练两阶段）作为可选子模块；向量检索评估。
